# JSON планировки — формат

Планировка — один JSON-файл: квартира «как есть» — `plan/as_is.json`, концепции серии —
`concepts/run-NN_<ГГГГ-ММ-ДД>/<name>.json` (их пишет генератор `src/concepts_runNN.py` через `tools/planlib.py`).
Из JSON строятся:

- `.plan` для RemPlanner — `python3 tools/remplanner_export.py <json…>` → `<name>.plan` рядом с JSON;
- проверки — `tools/check_layout.py` (эргономика, `ERGONOMICS.md`) и `tools/check_rules.py` (правила жильцов,
  `rules.json` — описание в `tools/reference/RULES.md`).

Что поле значит для RemPlanner, проверено импортом сгенерированных файлов (см. `REMPLANNER_V3_SCHEMA.md`); где
это не так — помечено «предположение». Поля, которые никто не читает (`note`, `name` у стен и т. п.), — для людей.

## Система координат

- Единицы — **см**. Ось x вправо, ось y **вниз**, начало — любое; удобно — левый верхний угол габаритного
  прямоугольника квартиры (у Г-образного контура выступы могут уйти в отрицательные координаты — это допустимо). Все прямоугольники — `rect: [x, y, ширина, высота]`, точки — `[x, y]`.
- `meta.mirror_vertical: true` — JSON нарисован отражённым по вертикали относительно того, что показывает
  RemPlanner (например, чертёж БТИ снят «вверх ногами»): экспортёр отражает y, `check_layout` меняет местами
  «слева/справа» у унитаза и раковины. Нет поля или `false` — RemPlanner показывает план как в JSON.
- Центр плана в RemPlanner (0, 0) — середина габарита всех `walls_bearing` (без них — `partitions`).
  Сдвиг и отражение делает экспортёр; в JSON ничего центрировать не нужно.
- Стороны `up | down | left | right` (`rp.back`) — в координатах JSON: `up` — к меньшим y.

## Верхний уровень

| ключ | что | читают |
|---|---|---|
| `meta` | заголовок и параметры плана | экспортёр, проверки |
| `walls_bearing` | несущие и наружные стены — каркас, в концепциях не меняется | все |
| `partitions` | перегородки — всё, что можно сносить и строить | все |
| `insulation` | утепление (лоджии и т. п.), необязательно | все |
| `windows` | окна и балконные блоки | все |
| `doors` | двери и проёмы | все |
| `fixed_elements` | точки канализации, стояки, вентканалы | `check_rules` |
| `furniture` | мебель, техника, сантехника | все |
| `zones` | свободные зоны перед приборами | `check_layout` |
| `rooms` | помещения с площадью | `check_rules`, `check_layout` (габарит) |
| `ergo_waivers` | уступки от «желательно» с обоснованием | `check_layout` |
| `structural_waivers` | уступки, которые навязывают несущие конструкции (в `plan/as_is.json`, `planlib` переносит в концепции) | `check_layout` |

Ключ верхнего уровня, который правило `window_full` из `rules.json` называет в `waiver` (например,
`"loggia_brick": "…обоснование…"`), — обоснование заложенного окна; см. `RULES.md`.

## meta

| поле | что | по умолчанию |
|---|---|---|
| `units` | `"cm"` | — |
| `title` | название концепции (печатается, в `.plan` не идёт) | — |
| `mirror_vertical` | см. «Система координат» | `false` |
| `outer_height`, `outer_width` | габарит квартиры по исходному чертежу; `outer_height` экспортёр берёт как высоту отражения (на результат не влияет — центр всё равно вычитается) | габарит `walls_bearing` |
| `ceiling_height` | высота потолка, для людей: стены в `.plan` всегда 270 (`rp_lib.HEIGHT`) | — |
| `origin`, `walls_rule` | пояснения | — |

## walls_bearing — каркас

`{"id", "rect", "kind", "note"}`. `kind`:

| `kind` | что | материал в `.plan` |
|---|---|---|
| `facade` | наружная стена | `a_brick` (кирпич) |
| `interapartment` | межквартирная / к лестничному холлу | `a_concrete` (бетон) |
| `column` | колонна, простенок, выступ каркаса | `a_concrete` (стеной, не `pillars`) |
| `bearing` | внутренняя несущая (в панельных домах — между комнатами) | `a_concrete` — предположение: своего образца нет |

В RemPlanner признака «несущая» нет, тип передаётся материалом (своя штриховка; проверено импортом для
`a_brick`, `a_concrete`, `a_block`). Как экспортёр строит стены:

- прямоугольник → осевая линия вдоль длинной стороны, толщина — короткая сторона;
- куски одной стены (тот же `kind`, то же поперечное сечение, на одной линии) сливаются, если соприкасаются или
  разрыв ≤ 130 см и в нём стоит дверь или окно. Стену с входной дверью можно задать двумя простенками
  (например `[0, 500, 25, 60]` и `[0, 650, 25, 60]` с дверью шириной 90 между ними): по отдельности такие куски легли бы поперёк;
- кусок тоньше 10 см вплотную к длинной грани более толстой параллельной несущей и в её пределах — накладка
  (уступ отделки, граница помещения для проверок): отдельной стеной не строится, её место остаётся в помещении;
- концы стыкуются сначала между несущими, затем с перегородками: угол — общий узел на пересечении осей,
  Т-примыкание — конец на грани проходящей стены (так сохраняет сам RemPlanner, иначе он не распознаёт помещения).
  Концы прямоугольников можно класть на грань или заводить друг на друга — стыковка сама дотянет их до осей.

Ригелей и потолочных балок в формате нет: их схема в `.plan` не получена (`REMPLANNER_V3_SCHEMA.md`, «Не
получено»). Ригель описывать в `note` соседней несущей стены.

## partitions, insulation

`partitions[]`: `{"id", "rect", "kind"?, "note"?}`, `kind`: нет — блок (`a_block`), `"glass"` — стекло (`a_glass`,
проверено импортом). Ориентация — по длинной стороне; кусок с меньшей стороной 10 и длиной < 10 (добор 9×10 у
двери) считается горизонтальным. Куски одной линии сливаются, если разрыв ≤ 130 с дверью в нём или ≤ 12 см и
поперечная стена в разрыве только заканчивается. Перегородка короче 10 по меньшей стороне — ошибка: дверь не
найдёт стену. Разрыв без двери RemPlanner объединяет в одно помещение (проверено импортом); проём без полотна —
дверь `kind: "doorway"`, помещения остаются раздельными.

`insulation[]`: `{"id", "rect", "note"?}` — слой утепления, выгружается стеной `a_block` и стыкуется последним,
не двигая другие стены (иначе помещение «протекало» в щель у фасада; проверено снимком).

## windows

| поле | что | по умолчанию |
|---|---|---|
| `id`, `rect` | прямоугольник окна в толще стены; длина — ширина проёма | — |
| `h` | высота окна, см | 150 |
| `sill` | низ окна от пола | 85 |
| `casements` | число створок (импорт 4 проверен) | 1 |
| `windoor_door` | id двери из `doors` — балконный блок: окно + дверь | — |

Окно ставится на стену, через которую проходит центр `rect`. **Балконный блок**: дверь из `doors` (`width`, `h` —
высота двери, по умолчанию 210) + окно `rect` (`h` — высота окна). `rect` — только оконная часть; проём двери — в `doors`, вплотную к окну;
длина блока = длина `rect` + `width` двери.
RemPlanner всегда ставит дверь блока у конца со стороны p1 стены (меньшая координата вдоль стены в RemPlanner;
проверено импортом) — экспортёр предупреждает, если дверь не у начала. Низ окна блока — `10 + h двери − h окна`.

## doors

| поле | что | по умолчанию |
|---|---|---|
| `id` | id; `door-entry` — входная (для совместимости) | — |
| `width` | ширина проёма, см | — |
| `hinge` | точка петли — край проёма; лежит на любой продольной линии в толще стены (грань или ось): стену экспортёр ищет по середине отрезка `hinge`–`other` | — |
| `other` | второй край проёма; `hinge` и `other` лежат на одной линии стены, `width` = расстояние между ними | — |
| `swing` | куда открывается полотно: единичный вектор `[0, -1]`, `[1, 0]`… в координатах JSON | — |
| `h` | высота, см | 210 |
| `kind` | тип проёма RemPlanner: нет — распашная `single`, `"doorway"` — проём без полотна (так же условно — купе и раздвижные: образца нет) | `single` |
| `entry` | `true` — входная дверь квартиры: от неё проверки ведут маршруты, её не проверяют `door_width`/`door_open`; экспортёр поле не читает | — |

Дверь балконного блока (на неё ссылается `windows[].windoor_door`) — проём в несущей стене: `door_width` её не
проверяет (как входную), `door_open` и правила открытого полотна — проверяют.
| `thick` | толщина стены у проёма, для людей | — |

Стена для двери — та, через которую проходит середина `hinge`–`other`. В `.plan` открывание задаётся `opening`
«сторона–петля» (проверено импортом). Вход — дверь с `"entry": true`, иначе с id `door-entry`.

## fixed_elements

| `kind` | поля | что |
|---|---|---|
| `drain` | `point` [x, y] (или `rect`) | точка подключения канализации: от неё `check_rules` строит трассы (`drain_routes`); без неё — `drain.point` из `rules.json`, иначе середина спинки унитаза «как есть» |
| `riser` | `point` или `rect` | стояк водоснабжения/канализации |
| `vent` | `rect` | вентканал |

`{"id", "kind", "point" | "rect", "name"?}` (`planlib.fixed`). В `.plan` не выгружаются: схема коммуникаций
RemPlanner не получена. Элементы без `kind` (`{"id", "point", "name"}`) — пометки для людей.

## furniture

`{"id", "rect", "name", "rp"}`: `rect` — габарит в плане (в координатах JSON), `name` — подпись для людей,
`rp` — привязка к каталогу RemPlanner (объект или список объектов на один `rect`). Без `rp` предмет в `.plan`
не попадает, но мешает проходам в проверках.

| поле `rp` | что |
|---|---|
| `name` | имя каталога: `rp_lib.CATALOG`, `tools/catalog/confirmed.json` или любое из полного каталога (`python3 tools/rp_catalog.py find <слово>`); группы `furniture`, `santeh_furniture` |
| `back` | сторона `rect`, к которой обращена спинка (бачок, изголовье, задняя стенка): `up` `down` `left` `right` |
| `angle` | точный угол RemPlanner (например, стул под 45°) вместо выведенного из `back`; `back` — ближайшая сторона для проверок |
| `over_floor` | число — низ предмета от пола, см (навесное) |
| `self_height` и другие поля | передаются в предмет `.plan` как есть (`width`/`height`/`self_height` импорт принимает) |
| `modules` | только для `name: "kitchen_run"` — см. ниже |

Габарит в RemPlanner: при `back` up/down ширина — по x, при left/right — по y. Предмет вне `CATALOG` и
`confirmed.json` (его ведёт скил remplanner-catalog: имена, подтверждённые снимком; файла может не быть) экспортёр строит по полному каталогу и печатает «не подтверждены импортом» — проверить на снимке.
Без полного каталога (`tools/catalog/remplanner_catalog.json` не собран) экспорт и проверки работают для имён
`CATALOG` (их сведения — `tools/reference/catalog_core.json`) и `confirmed.json` с копией записи каталога
(`python3 tools/rp_catalog.py confirm <name>`); на прочих имена останавливаются с перечнем `furniture <id>: rp.name`
и командой `fetch`.

**Линия кухни** `{"name": "kitchen_run", "back": …, "modules": [...]}` — модули встают вдоль `rect` от его начала
(меньшая x или y в JSON): сокращения `sink` (шкаф + мойка), `box`, `stove`, `washer`, `dishwasher` — по 60 см, или
имя каталога (ширина — из каталога). Столешница кладётся поверх всего, кроме плиты (у имён каталога — если
`custom_type: table_top`); остаток `rect` после модулей — тоже столешница.

## zones

`{"id", "rect", "name"}` — свободное место, которое нужно сохранить (перед унитазом ≥ 60–70, раковиной ≥ 70,
входом в душ ≥ 70–90; `ERGONOMICS.md`). `check_layout` ведёт к каждой зоне проход от входа. В `.plan` не идут.

## rooms

`{"id", "name", "area", "rect"?, "note"?}`: `area` — м² (как считал автор; RemPlanner считает свою по стенам),
`rect` — для проверок «предмет в комнате» (центр предмета внутри `rect`). Роль комнаты — по префиксу `id`
(`bath*`, `wc*`, `bed*`, `kitchen*`… — роли и префиксы задаёт `rules.json`, `RULES.md`). Мокрым комнатам, спальне
и комнате со столом `rect` нужен. В `.plan` не идут: помещения RemPlanner строит сам.
`bti_area` — площадь по экспликации БТИ (`planlib.room(..., bti=…)`): `planlib.save` печатает разницу с `area`.

Сложные случаи:

| случай | как задать |
|---|---|
| помещение не прямоугольник (Г, ниша) | `area` — `planlib.area(*rects, minus=[…])`; `rect` — основная часть, где стоят предметы |
| две зоны без стены между ними (кухня-прихожая) | две комнаты, у каждой свой `rect`: `kitchen…` (мокрая роль) и, например, `hall`; граница — условная |
| короб ГКЛ, инсталляция | `partitions` с `note` «короб» (толщина — глубина короба) |
| бетонный массив, пилон | `walls_bearing`, `kind: "column"` |
| двустворчатая дверь | образца нет: одна дверь шириной проёма, в `note` — «2 створки» |

## ergo_waivers

`{"<правило>" | "<правило>:<начало id объекта>": "что выигрываем"}` — принятые уступки от «желательно»
(`ERGONOMICS.md`, `planlib.waive`). Уступка без записи — проблема в `check_layout`, запись без уступки — тоже.

## structural_waivers

`{"<правило>" | "<правило>:<начало id объекта>": "причина"}` — в `plan/as_is.json`: уступки от «желательно»,
которые навязывают несущие конструкции (их пользователь изменить не может), например
`{"pass_main:door-kitchen": "коридор 80 между межквартирной стеной и пилоном"}`. `planlib.as_is()` и
`planlib.blank()` переносят поле в каждую концепцию. `check_layout` считает такую уступку обоснованной, баллы
бюджета за неё не берёт и печатает при `-w` отдельно («≈ из-за несущего»); запись, которая в концепции не
понадобилась, не ошибка. Ниже «минимально допустимо» несущее не оправдывает — такая концепция не проходит.
Сужение прохода (`pass_any`, `pass_main`) между двумя несущими стенами распознаётся само: если горлышко самого
широкого пути зажато несущими с обеих сторон, уступка записи не требует.

## Минимальный пример

```json
{
 "meta": {"units": "cm", "title": "Студия: пример", "mirror_vertical": false},
 "walls_bearing": [
  {"id": "top", "rect": [0, 0, 600, 20], "kind": "facade"},
  {"id": "bottom", "rect": [0, 480, 600, 20], "kind": "interapartment"},
  {"id": "left", "rect": [0, 0, 20, 500], "kind": "interapartment"},
  {"id": "right", "rect": [580, 0, 20, 500], "kind": "facade"}
 ],
 "partitions": [
  {"id": "bath-top", "rect": [20, 300, 200, 10]},
  {"id": "bath-right", "rect": [210, 310, 10, 170]}
 ],
 "windows": [{"id": "win", "rect": [200, 0, 150, 20], "h": 150, "sill": 85}],
 "doors": [
  {"id": "door-entry", "width": 90, "hinge": [490, 480], "other": [400, 480], "swing": [0, -1], "entry": true},
  {"id": "door-bath", "width": 80, "hinge": [210, 320], "other": [210, 400], "swing": [1, 0]}
 ],
 "fixed_elements": [{"id": "drain", "kind": "drain", "point": [69, 470]}],
 "furniture": [
  {"id": "wc", "rect": [50, 405, 38, 65], "name": "унитаз", "rp": {"name": "toilet", "back": "down"}},
  {"id": "bed", "rect": [340, 40, 160, 200], "name": "кровать", "rp": {"name": "bed_double", "back": "up"}}
 ],
 "zones": [{"id": "z-wc", "rect": [34, 340, 70, 65], "name": "перед унитазом"}],
 "rooms": [
  {"id": "bath", "name": "Санузел", "area": 3.23, "rect": [20, 310, 190, 170]},
  {"id": "living", "name": "Комната", "area": 25.6}
 ],
 "ergo_waivers": {}
}
```

Здесь вход — в межквартирной стене `bottom` между x 400 и 490 (стена — сплошной прямоугольник, проём режет
экспортёр), дверь открывается внутрь квартиры (`swing` [0, -1] — к меньшим y); дверь санузла — в перегородке
`bath-right`, открывается в комнату. `python3 tools/remplanner_export.py plan/as_is.json` → `plan/as_is.plan`.
