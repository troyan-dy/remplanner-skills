# RemPlanner в браузере — проверенные приёмы

Браузер открывать только для двух задач: **снимки планов** и **новый примитив** (тип предмета/проёма/поля, которого
нет в `rp_lib.CATALOG`, `tools/catalog/confirmed.json` и `REMPLANNER_V3_SCHEMA.md`). Импорт, площади и мебель
отдельно глазами не проверять: снимок «Перегородок» и есть проверка импорта. Если расширение не отвечает после
2 попыток — сказать пользователю.

Координаты ниже сняты при области страницы 1485×812 (и отдельно — для 1512×771 и 1568×773). Окно может быть
другого размера — тогда пересчитать по одному обзорному снимку (`screenshot`, `scale` 0.4). Где можно, кликать
по `ref`, а не по координатам.

## Снимки серии (вкладка «Перегородки»)

1. `tabs_context_mcp` (`createIfEmpty`), затем **один** `browser_batch`:
   `navigate` https://remplanner.ru/planner/ → `wait` 3 → клик по иконке меню «Скачать/загрузить файл» (≈ 70,100) →
   `wait` 1 → `find` «file input near 'Загрузить файл .plan'» → `find` «tab 'Перегородки' in top sheet bar» →
   `screenshot` scale 0.4.
   Резервную копию проекта перед импортом не скачивать и после снимков не восстанавливать: выгрузка из UI
   автоматизацией ненадёжна (см. «Полный каталог» ниже), а гостевой проект и так перезаписывается импортом.
   Поле `.plan` появляется только при открытом меню (обычно `ref_68`). Поле, которое `find` находит до этого, —
   загрузка картинки-подложки, в него `.plan` не грузится.
2. **Все планы серии — пакетами `browser_batch`**, на каждый план:
   `file_upload` (ref поля `.plan`) → клик по пустому полю (≈ 1180,690; снимает заставку «Нажмите, чтобы
   продолжить») → `wait` 3 → клик по ref «Перегородки» → `wait` 1 → клик (≈ 1180,690) → `wait` 2 →
   `zoom` region ≈ [418,160,1070,762], `save_to_disk: true`, **без** `scale` (со `scale` сохраняется уменьшенная копия).
   **Окно 1512×771:** план на «Перегородках» — x ≈ 510…1050, y ≈ 150…710; `zoom` region
   `[490,140,1070,725]` (это углы x0, y0, x1, y1, не ширина и высота); пустое поле для кликов — (300,600). Клик
   по (1180,690) при этом размере открывает окно «Быстрые клавиши» (закрыть — «закрыть окно» ≈ (906,184)).
   Пакет из 10 планов (≈ 80 действий) обрывал связь с расширением («Browser extension is not connected») дважды подряд;
   пакеты по 2 плана прошли без сбоев.
   Окно может смениться (например, с 1485×812 на 1512×771) посреди сессии — тогда `zoom` с прежней областью падает
   с ошибкой «Region exceeds viewport»; дальше — координаты для нового размера. `zoom` со `scale` сохраняет
   уменьшенную копию — пересъёмка нужна, и `save_shots.py` тогда берёт не те файлы: копировать по номеру в имени.
3. Снимки из ответа пакета уже видны — это и есть проверка. Переснять только план, на котором активен
   «Исходный план» (мебель яркая, нет размеров) или видна заставка. Отдельных проверочных снимков не делать.
   Ещё признак сбоя: на «Перегородках» нет мебели и подписей площадей — импорт оборвался; загрузить
   тот же файл ещё раз (сбой плавающий, см. REMPLANNER_V3_SCHEMA.md «Не получено»).
4. `python3 tools/save_shots.py screenshots/run-NN_<name1>.png …` — в том же порядке, что планы в пакете
   (берёт последние N снимков расширения). Для базовых планов — `screenshots/base_<name>.png`.
5. `tabs_close_mcp`.
6. Отправить пользователю снимки.

## Новый предмет каталога → образец

- Лист «Мебель» в верхней панели листов → значки разделов слева; подразделы раскрываются наведением,
  если не раскрылись — клик.
- Поиск: «Поиск предметов» внизу каталога → ввести текст → `Enter` → «Найти». Выдача иногда не обновляется —
  нажать «Найти» ещё раз; если текст не попал в поле — ввести заново.
- Поставить: предмет в выдаче → клик по свободному месту плана вне меню. `Escape` до клика отменяет выбор.
  Между кликами пауза ~1 с, иначе клики теряются.
- Ставить сразу все нужные предметы, затем одна выгрузка («Скачать только текущий план») → образец в
  `tools/reference/remplanner_example_v3_<что>.plan` → разбор в `REMPLANNER_V3_SCHEMA.md`. Предмет полного каталога,
  который встал на место на снимке, — в `tools/catalog/confirmed.json` (`rp_lib.CATALOG` в `tools/` перезаписывается
  установкой). Если в `~/Downloads` старый файл — выгрузка не сработала, повторить через раскрытое меню.
- Материал стены: правый клик по стене → «Материал». Выпадающий список переиспользуется между меню — брать ref
  из свежего `find`.
- Названия помещений через автоматизацию ввести не удалось (вкладка «Помещения»).

## Полный каталог (`tools/rp_catalog.py`)

- Параметры всех инструментов — публичный `planner.tools___<ver>.js` (`window.global_tools`). Обычно хватает
  `python3 tools/rp_catalog.py fetch` (сам находит имя через `POST /planner/create/`, см. REMPLANNER_V3_SCHEMA.md
  «Полный каталог»). Вручную: имя — из `performance.getEntriesByType('resource')` страницы редактора
  (`read_network_requests` после загрузки страницы пуст — кэш), затем `fetch <имя>`.
- Дерево меню — только в DOM: `.planner_ui_subtools[data-parent=group<id раздела>]` → `.subtools_group` (первый
  `.subtools_item.group` — заголовок) → `.subtools_item#plannertool_<name>.toolid<id>`, описание —
  `.tools_item_about[data-text]`, PRO — класс `is_pro`; предметы вне `.subtools_group` идут без группы.
  Снятое дерево — `tools/reference/remplanner_catalog_menu.txt`.
- Вывести большой текст со страницы: `javascript_tool` режет ответ (~1000 знаков, а строки с `=`/`?` блокирует),
  `get_page_text` отдаёт до 50 000 — положить текст в `<pre>` вместо `body` (вкладку потом перезагрузить).
  `fetch` со страницы на `http://127.0.0.1` расширение не пропускает (обрывает соединение).
- При области 1523×784 иконка меню «Скачать/загрузить» была ≈ (40,60), а не (70,100); клик по ref
  «Скачать только текущий план» без раскрытого подменю ничего не скачал; через раскрытое подменю — тоже нет
  (дважды, `~/Downloads` без нового файла). Вероятно, Chrome блокирует повторные автоматические загрузки с сайта —
  предположение; пользователю — разрешить загрузки для remplanner.ru.

## Область 1568×773

- Меню «Скачать/загрузить» ≈ (40,60), снять заставку — клик (1250,650), снимок плана — `zoom` [470,120,1100,700].
  `ref` поля `.plan` (`ref_68`) и вкладки «Перегородки» (`ref_25`) живут всю сессию и после переподключения.
- Пакет из 5 планов прошёл, следующий длинный пакет дважды оборвался: «Browser extension is not connected».
  После обрыва `tabs_context_mcp` снова подключает. Надёжно — **один план на пакет** и сразу `save_shots.py` с одним
  именем, тогда порядок снимков не путается.
- Резервная выгрузка опять не скачалась (наведение и клик по «Скачать файл .plan», затем «Скачать только текущий план»).
  Вернуть прежний план можно только импортом его `.plan` (например, `plan/as_is.plan`).
