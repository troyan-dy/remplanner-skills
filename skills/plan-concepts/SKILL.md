# Серия концепций

Одна **серия** — папка `concepts/run-NN_<ГГГГ-ММ-ДД>/` с несколькими **концепциями**: разными подходами
к квартире, а не вариациями одной. Каждая концепция проходит проверки, круг критики и выгружается в RemPlanner.
Прошлые серии остаются как есть: из их генераторов импортируются **блоки** (функции, которые строят санузел,
кухню, прихожую…).

Нужны `plan/as_is.json` (`/trace-bti`) и `REQUIREMENTS.md` с правилами (`/interview-household`). Чего-то нет —
скажи пользователю, какой скил набрать, и остановись.

**Контекст серии** — только эти источники: `REQUIREMENTS.md`, `rules.json`, вывод `python3 tools/blocks.py`
(индекс блоков всех генераторов), README и генератор последней серии. Исходник блока из прошлых серий открывай
по имени функции, точечно; справочники `tools/reference/` целиком не читай — в них ищут по месту.

## 1. Бриф серии

Определи номер NN (следующий после последней папки в `concepts/`) и что серия решает: новые правила
и раздел «Замечания — ещё не учтены» в `REQUIREMENTS.md`, выводы README прошлой серии. Набросай 5–10
концепций: имя, одна строка «в чём подход», какие правила и замечания он закрывает. Подходы должны
отличаться решением (где спальня, какой санузел, где кухня), а не мебелью.

Покажи бриф пользователю одним сообщением и получи «да» или правки. Готово, когда каждое замечание из
«ещё не учтены» закрыто хотя бы одной концепцией или отложено с причиной.

## 2. Генератор

`src/concepts_runNN.py` создаётся одним Write, дальше правится точечными Edit в функции нужной концепции.
API — docstring `tools/planlib.py`; блоки — импорт из прошлых генераторов. Пиши JSON в
`concepts/run-NN_<дата>/<name>.json`, генератор печатает площади.

Предметы подбирай под задачу и правила пользователя из полного каталога, а не только из привычных: для каждой
зоны вызови Skill tool с `remplanner-catalog`, он даёт габарит, высоту над полом, подводки и правило группы.

Перед сантехникой рисуй `zones`. Несущее и ограничения мокрых зон — из блока «Планировка» в `CLAUDE.md`.

Готово, когда `python3 src/concepts_runNN.py` записал JSON всех концепций брифа.

## 3. Проверки

Вызови Skill tool с `check-plan` для `concepts/run-NN_*/*.json`. Готово, когда каждая концепция `ok`
по эргономике и по правилам пользователя, каждая уступка обоснована в `ergo_waivers` и умещается в бюджет,
а ручные проверки из `check-plan` («Чего проверки не видят») пройдены.

## 4. Критика

Сразу после зелёных проверок вызови Skill tool с `critique-plan` — критик работает в фоне. Шаг обязателен:
критик стабильно находит то, что проверки пропускают при `ok` (двери против проходов, назначение предметов). Пока он читает,
пиши README серии (шаг 6). Его замечания (до 10, самые весомые первыми) вноси в генератор или отклоняй
с причиной в README. Пользователь просит больше кругов — повторяй шаги 3–4.

Готово, когда каждое замечание внесено или отклонено с причиной и проверки снова `ok`.

## 5. Выгрузка и снимки

1. Вызови Skill tool с `remplanner-export` для `concepts/run-NN_*/*.json`.
2. Вызови Skill tool с `remplanner-screenshots` для всех `.plan` серии → `screenshots/run-NN_<name>.png`.
   Снимки — один раз, по финальным планам после всех кругов правок. Браузер недоступен — скажи пользователю
   и отдай `.plan`: он откроет их в RemPlanner сам.

## 6. README серии

`concepts/run-NN_<дата>/README.md` по шаблону [SERIES-README.md](SERIES-README.md): суть каждой концепции,
какие правила и замечания учтены, площади, принятые уступки (вывод `python3 tools/check_layout.py -w …`),
что не вошло и почему, риски.

## 7. Итог

Если проект — git-репозиторий, закоммить серию одним коммитом (генератор, JSON, `.plan`, README, снимки).
Покажи пользователю снимки и короткую таблицу концепций. Следующий шаг: посмотреть понравившиеся планы
в RemPlanner и набрать `/plan-feedback`.

Готово, когда у каждой концепции есть JSON, `.plan`, снимок (или пользователь знает, что снимков нет) и раздел
в README серии.
