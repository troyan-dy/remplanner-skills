# Круг критики

Критик — свежий субагент без истории разговора: он видит планы так, как увидит их пользователь, и не оправдывает
решения, которые агент уже принял. Снимки ему не нужны: он работает по JSON и выводу проверок.

## 1. Собери материал

- пути JSON концепций серии и README прошлой серии (если есть);
- вывод `python3 tools/check_layout.py -w <json…>` и `python3 tools/check_rules.py -v <json…>`;
- `REQUIREMENTS.md` (правила п. N и сценарии жильцов).

## 2. Запусти критика

Субагент общего назначения, в фоне, с промптом из [CRITIC-PROMPT.md](CRITIC-PROMPT.md), куда подставлены пути
и вывод проверок. Пока он работает, продолжай свою работу (обычно README серии). Субагентов нет — прочитай
CRITIC-PROMPT.md и выполни его сам, в отдельном проходе, не глядя на свои заметки к серии.

## 3. Разбери ответ

Каждое замечание — в одну из трёх групп:

| Группа | Что делать |
|---|---|
| верно, правка понятна | внести в генератор, перезапустить проверки |
| верно, но решает пользователь (вкус, бюджет, его правило) | вопрос в README серии или пользователю |
| неверно (критик не знал факта о квартире или правила) | отклонить, причина — в README «Что не вошло и почему» |

Готово, когда каждое замечание в одной из групп, правки внесены и проверки снова `ok`.
